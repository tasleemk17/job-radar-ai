# Deploying Job Radar for free

Three free services, each doing one job. No credit card is needed for any of them at the time of writing; free plans change, so check each site if something looks different.

| Part | Service | Why |
|---|---|---|
| Website | **Vercel** | Static hosting with HTTPS, always on, fast |
| API | **Render** (free web service) | Runs the Docker image from this repo |
| Database | **Neon** (free Postgres) | Render's free disk is erased on every restart, so the data must live elsewhere |

```
browser ──► Vercel (React site) ──► Render (FastAPI) ──► Neon (Postgres)
```

The API was tested against Postgres 16 with the same 38 tests that run on SQLite, and the Docker image was run with `PORT` and a Postgres `DATABASE_URL` the way Render does.

## 1. Database: Neon

1. Sign up at https://neon.com (GitHub login is fine).
2. Create a project. Name it `job-radar`, pick the region closest to your users (Singapore for India).
3. Open **Connect** and copy the connection string. It looks like `postgresql://user:password@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
4. Keep it private. Anyone with it can read and change the database.

You can paste it as it is: the app rewrites the `postgresql://` start to the driver it uses.

## 2. API: Render

1. Sign up at https://render.com with GitHub.
2. **New > Blueprint**, choose this repository. Render reads `render.yaml`.
3. It asks for the values marked private:

| Variable | What to enter |
|---|---|
| `DATABASE_URL` | The Neon connection string from step 1 |
| `CORS_ORIGINS` | Your website address, for example `https://job-radar-ai.vercel.app` (you can correct it in step 4) |
| `ADZUNA_APP_ID`, `ADZUNA_APP_KEY` | Your Adzuna keys, or leave empty to skip Adzuna |
| `JOOBLE_API_KEY` | Your Jooble key, or leave empty to skip Jooble |

`JWT_SECRET` is generated by Render. Remotive and Arbeitnow need no key, so jobs appear even with the fields above empty.

4. Press **Apply** and wait for the first deploy (a few minutes).
5. Copy the service address (for example `https://job-radar-api.onrender.com`) and open `/api/health` on it. You should see `{"status":"ok"}`.

## 3. Website: Vercel

1. Sign up at https://vercel.com with GitHub.
2. **Add New > Project**, import this repository.
3. Set **Root Directory** to `frontend`. The framework is detected as Vite.
4. Under **Environment Variables** add `VITE_API_BASE` with the Render address from step 2, with no slash at the end.
5. **Deploy**. Naming the project `job-radar-ai` gives `https://job-radar-ai.vercel.app`.

## 4. Connect the two

In Render, open the service > **Environment** and make sure `CORS_ORIGINS` is exactly the Vercel address (`https://`, no slash at the end). Saving restarts the API.

Open the Vercel address and create an account. The first request after a quiet period is slow (see below); the sign-in page says so.

## Things to know about the free plans

- **The API sleeps after 15 minutes without visitors** and takes about a minute to wake. The sign-in page wakes it as soon as it opens and explains the wait. To keep it awake, a free monitor such as UptimeRobot can open `https://<your-api>/api/health` every 5 minutes. Render gives 750 free hours a month, which covers one always-on service. Render may still restart free services at any time.
- **Jobs refresh on every start** when the newest one is older than 6 hours, and then every 6 hours while the API is awake. The **Fetch new jobs** button works as well.
- **Neon suspends the database after 5 idle minutes** and resumes in about a second on the next request.
- **Anyone can create an account.** Passwords are hashed, but treat the site as a demo and do not share real personal data on it.
- **Claude is off unless you set `ANTHROPIC_API_KEY`**, and analysis and cover letters then use the built-in rule-based answers. If you do turn it on, set a monthly spend limit in the Anthropic console first: each account may make 30 AI calls an hour, but accounts are free to create.

## If something is off

| What you see | Cause and fix |
|---|---|
| "Failed to fetch" or a long wait | The API is asleep or starting. Wait a minute. |
| Browser console says a request was blocked by CORS | `CORS_ORIGINS` in Render is not exactly the Vercel address. |
| Page reloads on `/board` show 404 | `frontend/vercel.json` is missing or the Root Directory is not `frontend`. |
| The site calls itself or shows no jobs | `VITE_API_BASE` was not set before the Vercel build. Set it, then redeploy. |
| Deploy fails on Render | Open the deploy log. The usual cause is an empty or wrong `DATABASE_URL`. |
